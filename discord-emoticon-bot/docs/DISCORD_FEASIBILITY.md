# Discord API 기능 가능 여부 조사

조사 시점: **2026-09-21** / 기준: Discord 공식 개발자 문서(docs.discord.com), discord.py 2.7.1

요구사항 §24에 따라 **코드보다 먼저** 확인한 내용이다. 구현은 여기서 "가능 / 조건부 가능"으로
판정된 범위 안에서만 이뤄졌고, "불가능" 항목은 우회하지 않고 대체 UX로 바꿨다.

---

## 1. 요청한 UX별 판정

| | 기능 | 판정 | 조건·근거 |
|---|---|---|---|
| A | `/e` 로 검색 | **가능** | 글로벌 Slash Command(CHAT_INPUT). 옵션 이름에 한글(`검색어`) 사용 가능 — 커맨드/옵션 이름 정규식이 `\p{L}`을 허용 |
| B | 검색 결과 여러 개를 한 화면에 | **가능** | Components V2 `MediaGallery`로 이미지 그리드. **한 갤러리에 최대 10장**, 메시지당 총 컴포넌트 40개 |
| C | 이미지 선택 | **가능** | String Select(옵션 **최대 25개**) + Button |
| D | 선택한 이모티콘을 대화에서 사용 | **조건부 가능** | 아래 2절 참고. **봇이 사용자 이름으로 메시지를 보내는 것은 불가능** |
| E | 서버 Custom Emoji 자동 등록 | **조건부 가능** | 서버당 50개(부스트 시 증가), 개당 **256 KiB**, `CREATE_GUILD_EXPRESSIONS` 권한 필요. 봇이 그 서버에 들어가 있어야 함 |
| F | 1:1 DM에서 사용 | **가능** | **User Install** + `contexts`에 `BOT_DM(1)`, `PRIVATE_CHANNEL(2)` 포함 |
| G | Group DM에서 사용 | **가능** | 위와 동일(`PRIVATE_CHANNEL`). 사용자 설치 앱은 본인이 들어가 있는 모든 서버·DM·그룹DM에서 보임 |

## 2. "이모티콘을 대화에서 사용한다"의 실제 구현 가능 범위

요구사항 §12의 네 가지 방식을 각각 확인했다.

| 방식 | 판정 | 설명 |
|---|---|---|
| 1. Discord Custom Emoji로 등록 | 조건부 | 서버 이모지는 50개 한도·권한 필요. **Application-Owned Emoji**(앱당 **2000개**)가 훨씬 낫지만, 이 이모지는 **앱이 보내는 메시지에서만 렌더링**되고 사용자가 입력창에 직접 칠 수는 없다. `USE_EXTERNAL_EMOJIS` 권한은 불필요 |
| 2. 메시지에 이미지 첨부 | **가능** | 인터랙션 응답/후속 메시지에 파일 첨부. 크게 보이고 서버·DM·그룹DM 모두 동작. **← 이 프로젝트의 기본 방식** |
| 3. 링크 전송 | 가능 | 가장 단순하지만 미리보기가 깨질 수 있어 채택하지 않음 |
| 4. Interaction에서 고른 뒤 메시지로 전송 | **가능** | 2번과 결합. 검색 패널은 ephemeral, 고른 것만 공개 전송 |

### 불가능한 것 (우회하지 않음)

- **봇이 사용자 계정으로 메시지를 보내는 것**: 불가능. 선택한 이모티콘은 앱 메시지로 전송되고,
  클라이언트에는 `{사용자} used /e` 형태로 표시된다. 사용자 토큰을 쓰는 셀프봇 방식은 ToS 위반이며 사용하지 않는다.
- **사용자의 이모지 피커(😀 버튼)에 내 이모티콘을 끼워 넣기**: 공식 API에 해당 기능이 없다.
- **`/e --emotion` 같은 플래그 문법**: Slash Command는 플래그를 지원하지 않는다.
  → `/e`를 인자 없이 실행했을 때 나오는 **[😐 감정으로 찾기] 버튼 → 감정 Select**로 대체했다.

## 3. 인터랙션 관련 제약 (구현에 직접 영향을 준 것)

- **초기 응답 3초 제한**: DB 조회 + 파일 읽기가 있으므로 모든 명령에서 `defer(ephemeral=True, thinking=True)` 후 followup으로 응답한다.
- **인터랙션 토큰 15분**: 패널 View의 timeout을 180초로 잡았다.
- **사용자 설치 앱은 인터랙션당 followup 최대 5개**: 앱이 그 서버에 설치되어 있지 않은 경우에 적용된다.
  현재 흐름은 `defer → 패널(1) → (선택) 공개 전송(1)`이라 한도 안에 있다.
- **`Use External Apps` 권한**: 서버에서 이 권한이 꺼져 있고 앱이 그 서버에 설치되어 있지 않으면,
  앱의 응답이 **강제로 ephemeral**이 된다. 즉 그 서버에서는 공개 전송이 본인에게만 보인다.
  → 해당 서버에서 공개로 쓰려면 앱을 **서버에도 설치**해야 한다. (이 프로젝트는 서버 설치·사용자 설치 모두 지원하도록 커맨드를 등록한다)
- **Components V2**: `content`, `embeds`, `stickers`, `poll`과 **같이 쓸 수 없다**. 텍스트는 `TextDisplay`로 넣어야 한다.
- **첨부 이미지 참조**: 갤러리 항목은 `attachment://<파일명>` 형식으로 같은 메시지의 첨부를 가리킨다.

## 4. 이모지 업로드 제약

| 항목 | 값 |
|---|---|
| 앱 소유 이모지 개수 | 2000 |
| 서버 이모지 개수 | 50 (부스트 레벨에 따라 증가) |
| 파일 크기 | **256 KiB** (초과 시 400) |
| 권장 해상도 | 128×128 |
| 허용 포맷 | JPEG, PNG, GIF, WebP, AVIF |
| 이모지 이름 | `[A-Za-z0-9_]` 2~32자 — **한글 이름 불가** (그래서 `emo{id}` 규칙으로 생성) |

## 5. 커맨드 등록 제약

- 글로벌 CHAT_INPUT 커맨드 100개, 서버당 하루 커맨드 생성 200회 제한.
- 글로벌 커맨드는 반영이 느리다 → 개발 중에는 `DISCORD_DEV_GUILD_ID`로 길드 동기화(즉시 반영).
- Select 옵션 25개, Autocomplete 선택지 25개, 옵션 이름/값 각 100자.

## 6. 필요한 인텐트·권한

- **Message Content Intent 불필요**: 일반 메시지를 읽지 않고 Application Command만 쓴다. 코드에서도 `Intents.none()`.
- OAuth2 scope: `applications.commands` (서버 설치 시 `bot` 추가).
- 서버 설치 시 권한 비트: 메시지 전송 권한만 있으면 되고, 서버 커스텀 이모지 등록까지 쓰려면 `Create Expressions`가 추가로 필요하다.
